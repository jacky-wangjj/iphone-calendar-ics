# 日历增强包 · .ics 生成脚本

按 PRD v0.2 生成 iPhone 可订阅的日历文件，两层独立：

| 层 | 脚本 | 内容 | 产物 |
|---|---|---|---|
| **主订阅层**（方案A，默认） | `generate-ics.cjs` | 法定节假日、调休补班、二十四节气、传统节日，仅关键日（59–62 条/年） | `calendar-{年}.ics` |
| **宜忌层**（方案B，可选） | `generate-yiji.cjs` | 黄历宜忌逐日一条（365 条/年），独立订阅链接 | `yiji-{年}.ics` |

两个脚本都支持**传多个年份**，此时除单年文件外，额外产出合并文件与固定地址文件（`calendar.ics` / `yiji.ics`），对应《订阅配置与托管方案》第四节「URL 永久固定」的要求。

## 快速开始

```bash
cd scripts
npm install                          # 仅首次，安装 lunar-javascript

node generate-ics.cjs 2026 2027      # 主订阅层：单年两份 + 合并 + 固定地址
node generate-yiji.cjs 2026 2027     # 宜忌层：同上
node verify.cjs ../output/calendar.ics 20
node verify.cjs ../output/yiji.ics 18
```

只生成某一年：`node generate-ics.cjs 2026`，产物为 `calendar-2026.ics`，不覆盖固定地址文件。

产物写入 `../output/`：

| 文件 | 说明 |
|---|---|
| `calendar.ics` | **固定订阅地址用**：多年合并，年更时整体覆盖，URL 永不变 |
| `yiji.ics` | 同上，宜忌层 |
| `calendar-2026-2027.ics` | 合并文件带年份的副本，便于核对 |
| `yiji-2026-2027.ics` | 同上 |
| `calendar-2026.ics` / `calendar-2027.ics` | 单年版，回看或分年订阅用 |
| `yiji-2026.ics` / `yiji-2027.ics` | 同上 |
| `{年}-数据核对表.md` | 与国务院文件逐条比对 + 全年事件清单（PRD 验收第 1 条） |
| `{年}-宜忌核对表.md` | 格式分布、节日日清单、诸事不宜清单、抽查 |

| 2026 | 33 | 6 | 62 | 国办通知，2025-11-04 发布 |
| 2027 | 29 | 5 | 59 | 国办通知，2026-11-05 发布 |

单独校验某一文件：

```bash
node verify.cjs ../output/yiji-2027.ics 18    # 第二个参数为标题字数上限
```

## 主订阅层规则对照

| PRD 条款 | 实现 |
|---|---|
| E1 法定节假日 | `{节日名}·休` |
| E1b 多日假期 | 正日 `{节日名}·休`；假期内独立传统节日（除夕）`{除夕}·休`；其余 `{节日名}假期·休` |
| E2 调休补班 | `{被调节假日名}·班` |
| E3 二十四节气 | `{节气名}` |
| E4 传统节日 | `{节日名}({农历月日})` |
| W3 同日冲突 | 唯一优先级：法定节假日 > 传统节日 > 节气，只出一条 |
| W1 未发布年份 | `holidays.json` 无该年数据时只生成节气/传统节日，**绝不推算放假安排** |
| U1 / U2 | 全天事件 + `TRANSP:TRANSPARENT`；标题 ≤ 20 字 |

## 宜忌层规则对照

| PRD 条款 | 实现 |
|---|---|
| O1 独立可选层 | 单独 `.ics` + 单独订阅链接，与主层完全解耦 |
| O2 口径 | 《钦定协纪辨方书》底本 + lunar 库（6tail, MIT）程序化推算，静态生成、零 API |
| O3 标题格式 | 普通日 `{农历} · 宜{A}，{B} 忌{C}`；节日/节气日 `{节日名}({农历}) · 宜{A} 忌{B}`（各取 1 项） |
| 无「忌」条目 | `{农历} · 宜{A}，{B}`（lunar 返回 `忌:["无"]` 时不写忌） |
| 诸事不宜 | `{农历} · 诸事不宜`；若当天是节日/节气则 `{节日名}({农历}) · 诸事不宜`，避免节气名丢失 |
| U6 描述留空 | 不输出 `DESCRIPTION`（verify 会检查） |
| U7 标题 ≤ 18 字 | 正文候选按信息量排序，超出则降级：先砍第 2 个宜，再砍农历括号 |

**占位词不展示**：lunar 返回的 `馀事勿取`、`余事勿取`、`无` 是占位语义（意为"其余不宜"），不作为宜/忌条目输出。

**取词优先级**（长度受限时谁先被牺牲）：
1. 节日/节气日：宜忌各 1 项优先（O3），先丢农历括号，再丢忌
2. 普通日：2 宜 1 忌 → 1 宜 1 忌 → 2 宜 → 1 宜

## 数据维护

法定节假日与调休补班**无法由历法推算**，必须按国务院通知人工录入 `data/holidays.json`：

```json
"2028": {
  "source": "国务院办公厅关于2028年部分节假日安排的通知",
  "publishedAt": "2027-11-XX",
  "url": "https://www.gov.cn/...",
  "holidays": [{ "name": "元旦", "start": "2028-01-01", "end": "2028-01-03", "officialDays": 3 }],
  "workdays": [{ "date": "2028-02-XX", "for": "春节" }]
}
```

新增年份只需追加一个 key，脚本无需改动。节气、传统节日、宜忌均由 lunar 库自动推算，无需录入。

## 年度更新流程

1. 每年 11 月国务院发布次年安排后，录入 `data/holidays.json`
2. 按「当年 + 次年」重新生成：`node generate-ics.cjs 2026 2027 && node generate-yiji.cjs 2026 2027`
3. `node verify.cjs` 校验
4. 与 `output/{年}-*.md` 核对表逐条人工复核
5. 用新的 `calendar.ics` / `yiji.ics` **覆盖**服务端同名文件，URL 不变（PRD E6）
6. 社交平台发布更新公告

**为什么装两年而不是一年**：用户在 12 月翻到次年 1 月时，若文件只装当年，会看到一片空白，以为订阅坏了。装「当年 + 次年」可平滑跨年。到了再下一年，整体覆盖时旧年份自动消失，无需手工清理。

## 技术细节

- **历法引擎**：`lunar-javascript`（6tail，MIT 协议），节气按自然日归属，已处理 23 点后交节的跨日问题
- **节气数据**：逐日调用 `getJieQi()` 判定，不依赖节气表 key 的年度边界
- **RFC5545**：CRLF 行尾、每行 ≤ 75 字节折行（按 UTF-8 字符边界切分）、标题内 `,` `;` `\` 转义 —— 逻辑集中在 `lib/ics.cjs`，两层共用一份实现
- **UID 稳定性**：`{日期}-{类型}-{事件年份}@calendar-enhance.local`。年份取自事件日期本身而非文件年份，因此单年文件与合并文件里同一天事件的 UID 完全一致；年更覆盖时客户端按 UID 更新，不会重复挂事件
